# Microsoft To Do 导出

Chrome 扩展，使用当前 Chrome 用户资料中的 Microsoft To Do 会话，将任务下载为 CSV 或 JSON。无需注册应用或填写 API 密钥。

## 安装

1. 在 Chrome 116 或更高版本中打开 `chrome://extensions`。
2. 开启「开发者模式」，选择「加载已解压的扩展程序」。
3. 选择包含 `manifest.json` 的项目根目录。
4. 从 Chrome 工具栏的「扩展程序」菜单打开「Microsoft To Do 导出」。

## 使用

1. 在侧栏选择「全部任务」「仅未完成」或「仅已完成」，设置读取动作间隔，然后点击「读取任务」。扩展会在当前 Chrome 用户资料中打开一个独立的 To Do 标签页。
2. 如果标签页出现 Microsoft 登录页面，请在该页手动登录。返回 To Do 后，扩展会自动开始读取。如果读取中途需要重新登录，登录后会从头读取所选范围。
3. 读取期间保持侧栏和 To Do 标签页打开。侧栏会显示当前清单和已读取的任务数。需要停止时，点击「取消读取」。
4. 读取完成后，点击「下载 CSV」或「下载 JSON」。两种格式可以依次下载，文件保存到 Chrome 的下载位置。

读取动作间隔默认为 `1000` 毫秒，扩展会记住上次设置。输入 `0` 时，页面就绪后立即继续读取。输入 `250–10000` 毫秒之间的整数，可控制切换清单、打开详情和滚动加载等动作的启动频率。单个动作可能触发多条请求，To Do 也会独立发送后台请求。

如果读取失败，按侧栏提示检查问题，再点击「重新读取」。如果下载失败或中断，保持侧栏打开，再次点击对应的下载按钮。若侧栏提示下载超时，可先到 Chrome 下载列表查看状态。

## 下载导出诊断日志

在平时使用的 Chrome 中打开扩展侧栏，按出现问题时的设置读取或下载。复现后点击「下载诊断日志」，从 Chrome 下载列表找到 `microsoft-todo-diagnostics-*.json`。关闭侧栏或重启 Chrome 后，也可以重新打开侧栏下载之前已保存的日志。

扩展在当前 Chrome 用户资料中自动保存最近 500 条诊断事件。报告记录读取、重试、传输、文件生成和下载各阶段，以及可用的错误码、任务数和 Chrome 下载中断原因。日志不会自动上传，也不会记录任务内容、清单名称、账号信息、URL、本地路径或原始错误文本。若 Chrome 本身退出或标签页崩溃，需要进程或网络线索时，可使用下方的 Windows 调试脚本。

## 导出范围与格式

扩展导出默认清单和自建清单中的任务。导出范围不含智能视图和附件文件。截止日期保留网页显示的文字，备注以纯文本导出。

- **CSV** 每条任务一行，可用 Excel 打开。列顺序为清单、标题、已完成、重要、截止日期、备注、子步骤。没有匹配任务时，文件只包含表头。
- **JSON** 按清单组织任务，保留没有匹配任务的清单，并分别记录每个子步骤的标题和完成状态。

扩展读取 `to-do.live.com` 网页上的任务，数据在浏览器内处理并暂存在侧栏内存中。关闭侧栏后，需要重新读取才能再次导出。

## 开发验证

在项目目录运行以下命令。测试使用虚构任务数据，覆盖筛选、读取间隔、取消、批次重试、导出格式和诊断报告。

```powershell
node --test tests/*.test.mjs
```

## 排查 Chrome 退出

在项目目录打开 Windows PowerShell，运行以下命令，用独立的 `.chrome-debug` 配置启动或复用 Chrome。

```powershell
.\start-chrome-debug.ps1
```

Chrome 调试端口固定为 `127.0.0.1:9222`。若端口被其他程序占用，脚本会提示并退出。首次启动时，在该窗口的 `chrome://extensions` 手动加载扩展，并在 To Do 标签页登录。配置保存在本机，同一配置可复用登录状态。

诊断需要 Node.js 22 或更高版本。运行以下命令开始记录，保持终端运行，再从侧栏读取和下载。

```powershell
.\start-chrome-debug.ps1 -Diagnose
```

日志写入 `.todo-diagnostics`，包含导出阶段、任务计数、同一 To Do 标签页发往 `to-do.live.com` 的请求数、1 秒和 10 秒滚动峰值、HTTP 4xx/5xx、请求失败数、JS 堆大小，以及崩溃或进程退出事件。日志不写入任务内容、完整 URL、请求头或请求体。

比较旧版和新版时，使用同一账号、清单范围和下载格式，分别从新打开的读取标签页开始。记录总任务量、间隔、`todo-tab-closed` 或 `final-sample` 中的 `peak1s`、`peak10s` 和 `errors`（包括 `429`），并对照最后一个 `export-stage`。监控只统计成功附加后看到的请求，首次导航的请求可能早于附加。`target-crashed` 表示已监控的标签页崩溃，`browser-process-exited` 表示 Chrome 进程退出。正常关窗也会产生退出事件，需要结合退出码、复现步骤和崩溃记录判断。
