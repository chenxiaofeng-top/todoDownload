# Microsoft To Do 导出

Chrome 扩展，使用当前 Chrome 用户资料中的 Microsoft To Do 会话，将任务下载为 CSV 或 JSON。无需注册应用或填写 API 密钥。

## 安装

1. 在 Chrome 116 或更高版本中打开 `chrome://extensions`。
2. 开启「开发者模式」，选择「加载已解压的扩展程序」。
3. 选择包含 `manifest.json` 的 `D:\code\todoDownload` 文件夹。
4. 从 Chrome 工具栏的「扩展程序」菜单打开「Microsoft To Do 导出」。

## 使用

1. 在侧栏选择「全部任务」「仅未完成」或「仅已完成」，设置读取动作间隔，然后点击「读取任务」。扩展会在同一个 Chrome 用户资料中打开一个独立的 To Do 标签页。若出现 Microsoft 登录页，请在该页手动登录。返回 To Do 后，扩展会自动继续。若读取中途要求重新登录，登录后会从头读取本次范围。
2. 保持侧栏和读取标签页打开。大型清单需要逐条读取详情，侧栏会显示当前清单和已读取数量。
3. 读取完成后，选择「下载 CSV」或「下载 JSON」。可以先后下载两种格式，文件保存到 Chrome 的下载位置。

默认间隔为 1000 毫秒，支持 250–10000 毫秒，会记住上次设置。间隔控制切换清单、打开详情、滚动加载等导出动作的启动频率。单个动作仍可能触发多条请求，To Do 也会独立发送后台请求。

导出包含默认清单及自建清单。智能视图会跳过。JSON 保留没有匹配任务的清单和子步骤结构，CSV 每条任务一行，可用 Excel 打开。没有匹配任务时，CSV 只包含表头。截止日期保留网页显示的文字，备注以纯文本导出。附件文件不在本版的导出范围内。

扩展只读取 `to-do.live.com` 网页上的任务。任务数据暂存在侧栏内存中，关闭侧栏后需要重新读取。若页面改版或读取数量不符，侧栏会显示失败原因，可以重新读取。

## 开发验证

在项目目录运行 `node --test tests/*.test.mjs`。测试使用虚构任务数据，覆盖筛选、限速、取消、批次重试及导出格式。

## 排查 Chrome 退出

在 Windows PowerShell 中运行 ` .\start-chrome-debug.ps1 `，用独立的 `.chrome-debug` 配置启动或复用 Chrome。CDP 固定监听 `127.0.0.1:9222`。若端口被其他程序占用，脚本会提示并退出。首次启动时，在该窗口的 `chrome://extensions` 手动加载本扩展，并在 To Do 标签页登录。配置保存在本机，同一配置可复用登录状态。

运行 ` .\start-chrome-debug.ps1 -Diagnose ` 开始记录，诊断需要 Node.js 22 或更高版本。保持终端运行，再从侧栏读取和下载。日志写入 `.todo-diagnostics`。其中包含导出阶段、任务计数、同一 To Do 标签页上发往 `to-do.live.com` 的请求数、1 秒和 10 秒滚动峰值、HTTP 4xx/5xx、请求失败数、JS 堆大小和崩溃或进程退出事件。日志不写入任务内容、完整 URL、请求头或请求体。

比较旧版和新版时，使用同一账号、清单范围和下载格式，分别从新打开的读取标签页开始。记录总任务量、间隔、`todo-tab-closed` 或 `final-sample` 中的 `peak1s`、`peak10s` 和 `errors`（包括 `429`），并对照最后一个 `export-stage`。监控只统计成功附加后看到的请求，首次导航的请求可能早于附加。`target-crashed` 表示已监控的标签页崩溃，`browser-process-exited` 表示 Chrome 进程退出。正常关窗也会产生退出事件，需要结合退出码、复现步骤和崩溃记录判断。
